# --- Stage 2b-1 hardening: band mode evaluation -----------------------------
# All existing 2048x2048 and 2000x1333 lines above still match byte for byte in
# "exact band" mode (band = canvas width x canvas height) on SingleTileStore and
# SparseTileStore at tile sizes 64 and 256:
#   exact256-vs-single 2048x2048: MATCH (31 phases, 0 bad)
#   exact64-vs-single  2048x2048: MATCH (31 phases, 0 bad)
#   exact256-vs-single 2000x1333: MATCH (31 phases, 0 bad)
#   exact64-vs-single  2000x1333: MATCH (31 phases, 0 bad)
#
# A strip band (canvas width x 512/1024 rows) was implemented, measured and
# REJECTED. It is pixel-identical across tile sizes (strip256-vs-strip64 MATCH
# on both canvases) but not identical to the dense oracle:
#
#   512-row strips, 2048x2048: max channel diff 64, worst phase 379 px
#     per phase: 00=0, 01=0, 02=6/6, 03=36/44, 04=36/51, 05..21=36/54,
#                22=36/376, 23=36/375, 24..30=64/376..379  (maxch/diffpx)
#   1024-row strips (fewer boundary-split dabs), 2048x2048: 37 px, maxch 64
#   1024-row strips, 2000x1333: 1 px, maxch 2
#   example pixels: (836,591)=fffe3232/ffff3232 (1409,604)=ff3cb45b/ff3cb55b
#
# The differing pixels sit on antialiased brush edges and grow with the number
# of dabs over-blended into them. Root cause: Skia resamples a scaled, filtered
# dab differently for a different absolute y in the destination surface, and a
# strip band necessarily changes that y (splitting a dab on a strip edge makes
# it worse). The proposed gate was max channel diff <= 1 and differing pixels
# < 0.01%, so strip mode was not shipped and no strip oracle is recorded.
# The exact band stays the only sparse band mode.
